# 质量门（六道，确定性）

`scripts/check.py` 是唯一的裁判。它有退出码：全过 `0`，有不过 `1`——所以能被挂在
提交前、CI、或"做完了没"的判断里，不靠谁的一句话。

```bash
python3 scripts/check.py                 # 全部套组
python3 scripts/check.py --only my-forest # 只看一套
python3 scripts/check.py --json          # 机器可读
```

## 六道门与阈值

| 门 | 阈值 | 为什么是这个数 |
| --- | --- | --- |
| **G1 令牌完整** | 7 个必备令牌一个不能少 | 缺令牌的"主题"装进宿主会在某些元素上掉回默认色，看起来像 bug |
| **G2 可读性** | 正文/面 ≥ **7**；辅助/底 ≥ **4.5** | WCAG AA 正文是 4.5，但长文阅读的舒适区下限是 7。辅助小字用 4.5（小字本来就难读，再低就是"看不清"而不是"淡雅"） |
| **G3 强调可读** | 强调色上文字 ≥ **4.5**；强调与底区分度 ≥ **3.0**（提示级） | 这条最容易翻车：按钮做得好看，字压上去看不见。本套件靠它抓出过 1.91:1、3.35:1、4.39:1 三个"隐形按钮" |
| **G4 真设计系统** | 结构规则 ≥ **6** 条 且 规则行 ≥ **12** 行 | 挡"只换了个色号"的假主题。这两条线是从 35 套的实际分布定的：护眼组最少（8 条/23 行），堆料组最多（40 条/117 行） |
| **G5 护眼专项** | 纸面亮度 ≤ 0.88；材质令牌全 `none`；无 `animation` | 只对 `group: care` 或标了 `eye_safe` 的套组生效。护眼的敌人不是"不够好看"，是纯白、纹理噪点、动效 |
| **G6 零资产依赖** | 不许残留 `url("/...")` | 套组要能发给别人。原作者私有素材必须变成 `--deco-x` 槽位（注释里出现路径不算） |

## 脚本查不到、必须用眼睛的部分

脚本管确定性，眼睛管审美和真实布局。每次交付前在真实宿主里过一遍这四问：

1. **侧栏导航有没有被挤出可视区？** 主题改了行高、字号、padding 之后，导航总高度会变。
   本套件在真实项目里就撞过 6 套把导航顶出去（最多 +93px）。改纵向尺寸后必须实测。
2. **长段落读着累不累？** 对比度达标 ≠ 舒服。行高、行宽、字号要一起看。
3. **切换主题后有没有残留？** 有些样式（比如 `transform`、`position`）不改回默认值就会
   在切走之后继续生效。
4. **关掉的面板还在占位吗？** 折叠态用 `display:none` 而不是只靠视觉隐藏。

## 一个反直觉的结论

**不要追求 21:1 的极值对比。** 纯黑白（21:1）在长文阅读里比 10:1 更累眼——过高的
对比会让眼睛不断重新调节。护眼组的实测值是 10–11:1，这是刻意的。
