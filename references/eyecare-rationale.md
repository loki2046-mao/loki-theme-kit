# 护眼主题为什么是这些数

作者近视，要求"至少要有一套能长久对着屏幕写东西/写代码的风格"。这一族（`care` 组：
`loki-ease` 纸墨·日 / `loki-ease-dark` 纸墨·夜 / `loki-moss` 雾苔）不算好看，全是为这条
服务。每个数字下面都有理由，不是审美偏好。

## 硬指标（`check.py` 的 G5 + G2 会查）

| 指标 | 目标值 | 实测 | 为什么 |
| --- | --- | --- | --- |
| 纸面相对亮度 | 0.72 – 0.86 | 0.818 / 0.827（深色版 0.011） | 低于 0.72 会开始"发灰"，高于 0.86 逼近纯白就开始刺眼 |
| 页面最亮色 | 不得是纯白 | `#f8f3e8` / `#ece5d6` | 纯白 `#fff`（亮度 1.0）在大面积使用时是眩光源 |
| 正文对比 | 7 – 12:1 | 10.05 / 11.02（夜 10.35） | 下限 7 是长文舒适线；**上限同样重要**——21:1 的纯黑白会让眼睛反复调节，比 10:1 更累 |
| 辅助小字 | ≥ 4.5:1 | 4.91 / 5.55 / 5.01 | 小字本来就难读，"淡雅"到 3.x 就是看不见 |
| 强调色上文字 | ≥ 4.5:1 | 5.18 / 4.97 / 7.52 | 链接和按钮字 |
| 装饰图案 | 0 处 | 0 | 纹理/噪点/网格会持续抢占注意力，且降低有效对比 |
| 动效 | 0 处 | 0 | 呼吸动画、渐变过渡在长时间阅读里是干扰 |

## 排版参数

| 参数 | 值 | 理由 |
| --- | --- | --- |
| 正文字号 | 15px | 14px 在长时间阅读里偏小；16px 会让每屏信息量下降 |
| 行高 | 1.85 | 中文没有词间空格，需要比英文更松 |
| 字距 | 0.01em | 中文字形密，极小的字距让眼睛更容易定位 |
| 行宽 | 38rem（中文约 40 字） | 超过 45 字，换行时眼睛回扫容易丢行 |
| 正文字体 | 衬线（宋体类） | 长文的横笔画对比更高，字形结构更易辨认 |
| 代码块 | 浅底深字（`#e7dfcd`） | 深底代码块在浅色页面里是"黑洞"，反复扫视会累 |
| 图片 | 压亮度 | 一张纯白底截图能瞬间破坏整个纸面的亮度区间 |

## 三条反直觉

1. **不要追最高对比。** 护眼不是"越黑白越好"，是"对比稳定、变化小"。
2. **不要用纯白 + 纯黑。** 两边都退一档（`#f8f3e8` / `#3a352e`）比 `#fff`/`#000` 舒服。
3. **护眼主题应该是最"没意思"的那一套。** 任何让你注意到的设计（炫的边框、动的元素）
   都在抢注意力，那正好与护眼目标相反。想好看的时候切别的套组就好——这正是要有 35 套的原因。

## 自测你自己的护眼主题

```bash
python3 scripts/check.py --only <你的套组>     # G5 只对 group=care 或 eye_safe:true 的套组生效
```

想让自己的套组也吃这套检查，在它的 `meta.json` 里写 `"group": "care"` 或 `"eye_safe": true`。
