# 踩过的坑（照着查，别重新踩）

这些不是"可能的注意事项"，是真实发生过的故障，每条都写了症状、原因、修法。

## 1. 主题切了，界面没变

**按顺序查这三处：**

1. **`data-theme` 放在哪个元素上了？** 套组全是 `:root[data-theme="x"]` 开头，也就是
   `<html>`。放在 `<body>` 或某个 div 上，一条都不会生效。
2. **样式引对了吗？** `index.css` 里的 `@import` 路径是相对它自己的，不是相对页面。
   把 `index.css` 放到别处而 CSS 文件没跟着动，就是静默失效（浏览器只在控制台提一句）。
3. **有没有被更高的优先级压住？** 宿主自己的规则如果写着 `.my-card { background: #fff }`，
   它和 `.loki-surface-strong`（都在单个 div 上）比的是**谁在后面 / 谁更具体**。修法是给
   宿主的规则加个父级（`.app .my-card`）而不是给主题加 `!important`——后者会在下一次
   改主题时炸回来。

## 2. 切主题时闪一下默认色

组件挂载后才恢复 localStorage 的话，第一帧一定画的是默认主题。修法是**在 `<head>` 里、
任何样式表之前**放一段内联脚本，先把 `data-theme` 设好（见 `templates/theme-switcher-flash-guard.html`）。
React 的 `useEffect` 抢不到这一帧，别在那儿纠结。

## 3. React 报 "A tree hydrated but some attributes ... didn't match"

localStorage / `window` 的值被读进了 `useState` 初值。服务端算出一个值、客户端首帧算出
另一个，两边 HTML 不一致。修法：

```tsx
const [theme, setTheme] = useState("loki-ease");     // 初值 = 服务端也能得到的值
useEffect(() => { setTheme(localStorage.getItem("loki_theme") ?? "loki-ease"); }, []);
```

这条是硬经验：本套件的作者在自己的应用里就是这么修掉面板宽度 hydration 报错的。

## 4. 侧栏导航最后一项被切掉 / 挤出可视区

主题改了行高、字号、padding，导航总高度就变了。**34 套里当年有 6 套把导航顶出可视区，
最多溢出 93px。** 这不是"某一套主题的 bug"，是"改了纵向尺寸就得重新量"。

自查脚本（在真实页面的 console 里跑）：

```js
const nav = document.querySelector(".loki-sidebar nav, .loki-sidebar");
console.log("溢出像素:", nav.scrollHeight - nav.clientHeight);   // 必须 ≤ 0
```

真溢出时的修法优先级：① 收紧该套自己的纵向 padding/行高；② 缩小字号；③ 给容器
`overflow-y: auto` 只是遮丑，不解决"用户看不到入口"。

## 5. 折叠的面板仍然占着布局

用 `height: 0` / `opacity: 0` / `visibility: hidden` 收起，元素仍然参与布局，把它下面的
东西挤出屏幕。**必须 `display: none`**（本套件的切换器 CSS 已经这么写了，收起来时
`.lk-theme-picker:not([open]) > .lk-theme-panel { display: none; }`）。

## 6. 主题之间"串味"：切走之后还有效果残留

某套主题在元素上写了 `transform: rotate(-.3deg)` 或 `position: absolute`，切到别的主题后
没有规则把它改回来，于是残留。修法：**每套主题只改"能被另一套覆盖"的属性**，或者在自己的
规则里把不想要的值显式写回默认（`transform: none`）。

## 7. 按钮做得好看了，但字看不见

强调色上文字对比不足是最常见的翻车点。本套件用 G3 这道门拦它，历史上抓到过 1.91:1、
3.35:1、4.39:1 三个"隐形按钮"。改的时候注意：**改 `--accent-ink` 往往比改强调色更划算**
（保住品牌色，只换字色）。

## 8. 打印 / 导出 PDF 一塌糊涂

深色主题打印出来是黑的。给打印单独加一段兜底：

```css
@media print {
  :root[data-theme] { --bg-canvas: #fff !important; --text-primary: #000 !important; }
}
```

## 9. 在 file:// 下 `document.styleSheets[...].cssRules` 抛 SecurityError

file:// 页面里读 CSSOM 会被安全策略拦住（**样式本身是生效的**，只是你读不到规则）。
想在控制台审查规则，用本地 http 服务打开（`python3 -m http.server`）。

## 10. `!important` 的诱惑

一时痛快，代价是下一套主题永远压不过它。本套件 35 套主题里 `!important` 出现 0 次。
宿主有更强规则时，改宿主的选择器，别用 `!important` 反打。

## 11. 接到别人家的宿主上：同一个令牌既当底色又当字色

把套组接到外部宿主（Cola 这类）时最容易翻的车：宿主把某个颜色令牌**当底色**用，而我们的主题
假设它**当强调字色**用。实测过两次：

- 宿主的列表行底色 = `--cola-highlight`。我们的主题里那是亮色强调色，行里的浅色标题压上去
  → **1.54:1**，整列读不清。
- 宿主又有 `button { color: var(--accent-ink) !important }`，把"压强调色的字色"套到了所有按钮上。
  深色主题里 accent-ink 是近黑，落到深色底上 → **1.03:1**。

**排查方式**：不要靠眼睛一处处找，跑一次「可读性扫描」——遍历可见元素，算它的字色与**有效背景色**
（沿祖先链找到第一个不透明背景）的对比度，< 4.5:1 的全部报出来。Cola 上第一次跑出 42 处，
改完再跑到 0；35 套主题 × 真实界面全绿。

**修法的优先级**：① 先看宿主自己的皮肤怎么处理同一个坑（多半已经踩过）；② 按"这个元素坐在什么
底上"分类改，不要一刀切改文字色（会继承到子元素，变出新的低对比）；③ 只在适配器层修，别去改套组
——套组要保持宿主无关。

## 12. 宿主已经有自己的皮肤/主题系统

这时**不要另起一套**。两套系统并存会同时出四个问题：两个切换器打架、悬浮面板挡内容、
我们的 UI 被宿主的全局规则污染（看不清）、两层皮肤叠着互相抵消（看起来"改了个寂寞"）。

正确做法（见 `adapters/README.md` 的 Cola 案例）：把我们的套组**注册成宿主的主题**
—— 用它的属性名、它的存储键、它的切换器面板，只在面板里多一个分组标题。
宿主自己那套一动，我们就让位。宿主已有完整设计系统时，还要跳过我们的"通用元素层"
（那层是给没有设计系统的普通页面用的，会跟它的按钮/标题样式打架）。

## 13. 同一个页面被注入两次，旧的那份还活着

换清单、重装、Agent 重跑 —— 只要注入两次，就会有**两代**同时活着：上一代的
`MutationObserver` 还挂着，会把自己那批面板条目又加回来。表现出来是
「我明明只留了 4 套，面板里还是 35 套」。

现在接入包里有**代际接管**：新的一份启动时先把上一代 `destroy()`（断观察器、摘条目、
删样式、去掉自己的属性），并且只动自己加的东西，宿主自己的皮肤和存储不碰。
（对早已注入的旧版本这不生效 —— 那种得让宿主页面重载一次。）

## 14. 角色匹配到 0 个，不一定是坏了

「渲染完发现某个角色一个元素都没匹配到」有两种原因：① 宿主升级改了 DOM；
② 那块界面现在根本没出现在屏幕上（比如发送按钮只在会话里才有，空状态只在没会话时才有）。

**少量**为 0 多半是 ②（不用动）；**大面积**为 0 才是 ①（跑 `--refresh`）。
`adapt.py --check` 按这个门槛判，不会因为一个临时不存在的按钮就把整个对照表重认一遍。

## 15. 宿主改不了源码怎么办

打包好的桌面 App（Electron/Chromium）改不了 `.app` 里的代码，但它通常带调试端口。这类宿主走
`scripts/inject-cdp.py`：注入 `<style>` + 一段脚本，**不落盘、不改安装包、重启即恢复**。
先用 `--eval` 读宿主自己的令牌与 DOM（谁定义了什么、哪些类名能钩），再决定适配器怎么写。

> 找宿主的令牌面：遍历 `document.styleSheets`，扫所有声明**值**里的 `var(--xxx)`，比只扫属性名
> 全得多（Cola 用 394 个令牌，其中绝大部分出现在工具类的值里）。
