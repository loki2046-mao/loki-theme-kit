# 结构件怎么过到别人的宿主里（角色绑定）

颜色那层靠令牌就能搬，**结构件不行**。这份文档讲的就是结构件那一层怎么接 —— 以及
为什么「接不上就让它自己去适配」这件事真的能做。

## 先分清两层

| | 颜色层 | 结构层 |
| --- | --- | --- |
| 内容 | 底色、文字、边框、圆角、投影、字体、四种状态色 | 纸面纹理、贴纸圆边、撕口、计数器编号、扫描线、四角准星、气泡尾巴、首字下沉、正文分栏 |
| 靠什么接 | 令牌（`--bg-canvas` → 宿主的变量） | CSS 选择器命中宿主元素（`.loki-sidebar`、`.loki-bubble-user`…） |
| 宿主要求 | 变量驱动就够 | **DOM 里得有可认领的位置** |
| 结果 | 任何宿主都能过 | 本套自带宿主能过；别人的宿主默认**全部落空** |

这就是「他的界面只有颜色变了，帅的那些没变」的来源。

## 解法：不改 35 套主题，改成给宿主挂钩子

原来那 35 套的结构层是挂在 `.loki-*` 这些语义钩子上的。**不改主题、不改宿主源码**，
而是在运行时把钩子类名**加到宿主的真实元素上**：

```
宿主 DOM                                 35 套结构层（一个字没改）
  <aside class="coding-cola-agent-sidebar">   ← tagger 加 class
  <button class="…">
        ↓                                        ↓
  class="… loki-sidebar"                   html[data-cola-skin="x"] .loki-sidebar { … }
```

于是每个宿主只需要一份**角色对照表**（`adapters/<宿主>/binding.json`），
而不是把 35 套主题重写 35 遍。

```
宿主 → probe.py 盘点 → binding.json（角色 → 宿主选择器） → tagger.js 挂钩子 → 35 套结构层生效
```

## 六步流程

```bash
# ① 盘点宿主：把界面抓回来，出角色候选（草案，会打印对照表）
python3 scripts/probe.py --port 9333 --dump /tmp/host-dom.json

# ② 定稿：把候选核一遍，写进 adapters/<宿主>/binding.json
#    （认错了改掉；认不出来的宁可不写 —— 空着只是那个装饰位没有，乱挂会弄坏界面）

# ③ 逐条实测：每个角色真的匹配到几个元素
python3 scripts/adapt.py --host cola --port 9333 --check

# ④ 隔离测试：这个钩子会不会把宿主排版弄坏
python3 scripts/adapt.py --host cola --port 9333 --triage          # 先看
python3 scripts/adapt.py --host cola --port 9333 --triage --apply  # 把该撤下的撤下

# ⑤ 挂着钩子看整体：结构件到了多少、整页有多少元素被改动
python3 scripts/adapt.py --host cola --port 9333 --verify

# ⑤′ 把「现在长什么样」记进对照表 —— 宿主升级后靠它判断新候选是不是原来那个东西
python3 scripts/adapt.py --host cola --port 9333 --stamp

# ⑥ 生成可注入的挂钩器，和套组 CSS 一起注入
python3 scripts/adapt.py --host cola --port 9333 --install --css /tmp/out/loki-themes.css
```

## 判定标准是算出来的，不是看出来的

`--triage` 逐钩子隔离测试（父层钩子的字号会传给子层，一起挂会把锅算到错的钩子头上，
所以**必须隔离**），量的是**整页几何**（连子孙一起，因为有些规则改的就是子元素）：

| 判定 | 条件 |
| --- | --- |
| ✗ 撤下 | 让任何元素 `display:none`；或改了骨架属性（`display/position/flex-direction/overflow/max-width/width/height/white-space`）；或整页 >30% 元素尺寸大变 |
| ⚠ 看着办 | 5%~30% 元素尺寸有变化 —— 报告给人看，人来定 |
| ✓ 保留 | 基本只动装饰（纹理/圆角/投影/裁切/前后缀） |

`--verify` 报三组硬数字：**装饰变化**（结构件真的起作用了）、**排版变化**（可能闯祸）、
**整页尺寸大变/被隐藏的元素数**（闯祸）。还有**结构件覆盖率**：每套主题用到的钩子里，
真正挂到了宿主元素上的比例 —— 这就是「帅的东西过来了多少」的可量化答案。

## 宿主升级了，怎么跟着升级

```bash
python3 scripts/adapt.py --host cola --port 9333 --refresh          # 先看
python3 scripts/adapt.py --host cola --port 9333 --refresh --apply  # 写回对照表
```

它做四件事：① 重新 `--check` 找出失效的角色；② 重新盘点宿主、给失效的角色找新位置并
实测新选择器（匹配 0 个的不会盲目采用）；③ 写回 `binding.json`（旧的存成 `.json.bak`，
并记 `refresh_log`）；④ 提示再跑一遍 `--verify`。

**而且不用等你发现**：`tagger.js` 里某个角色一个元素都匹配不到时，会往宿主控制台
`console.warn` 一句，并说清「跑 `--refresh`」。宿主升级把 DOM 改掉，就是靠这条第一时间知道的。

## Cola 上跑出来的真实数据（2026-09-13）

| 项 | 结果 |
| --- | --- |
| 定稿角色 | 26 个（认领宿主元素 170～297 个，随界面状态浮动） |
| 结构件覆盖率 | **35 套平均 80.3%**（该套用到的钩子里，真正挂到宿主元素上的比例） |
| 装饰变化 | 104 处（纹理/圆角/投影/裁切/前后缀真的在动） |
| 隐藏元素 | **0** |
| 截图对照 | 同一套主题，有结构件 vs 只有颜色：改动像素 老式桌面 **11.6%**、八位 **10.1%**、贴纸波普 **5.6%**（集中在聊天主区） |
| 撤下 3 个 | `nav-group`（侧栏宽度 231.98→197.98px）、`chat-stream`（消息流左内边距 24→96px）、`composer`（输入区 display 被接管） |
| 要人看一眼 | `nav-icon`（display: block→grid、14→20px） |
| 认不出来的钩子 | 品牌区、空状态、弹层、主题色卡、IP 形象框（**IP 形象是红线，不碰**）|

它为什么没有 100%：三类原因，都不是“没干完活”——

1. **宿主里根本没有那个位置**（没有独立品牌区元素、空状态只在无会话时出现）；
2. **语义对不上被主动撤下**（给 32px 高的标题栏套贴纸边框 → 文字被裁，只能撤）；
3. **红线**（IP 形象一律不碰）。

还差一个已知缺口：**侧栏的装饰几乎没显出来**。原因很实在——它那 51 行会话本身是透明的、
没有底色可选，只给它们加 `border-radius` 是看不见的。要让它显，得给这个宿主补几条
专属规则（先给行加一层浅底，再让圆角/描边上场），那属于“为宿主定做”的活，跟令牌适配分开算。

## 自动恢复（开机就不掉）

注入型的宿主重启就掉。两条路：对 Agent 说一句「把外观恢复回来」（`profile.py restore`），
或者装常驻守护（`profile.py autostart`）—— 后者每 5 秒巡检一次，宿主一起来就自动注回去。
守护的三条纪律见 `scripts/daemon.py` 开头，关键是**不抢宿主自己的皮肤系统**：用户选的是宿主
自带的皮肤、而宿主样式还没进页面时，要**等它先注**（我们抢先打标记会让它让位，用户反而看到
一套没样式的皮肤）。实测过共存：两边守护同时在跑，宿主那套皮肤全须全尾，我们的 35 套也在
宿主面板里等着被点。

## 升级路径实测（不是只有设计，真跑过）

两个场景都实测了（把对照表故意弄坏，模拟宿主升级改名）：

| 场景 | 结果 |
| --- | --- |
| 失效角色的新位置**形状对得上** | 自动改好并写回（`refresh_log` 里留 `{"auto_fixed": {"table": "table"}}`），只花一条命令 |
| 新候选**形状不对**（比如侧栏候选实际是那个 2637px 高的会话列表） | **拒绝采用**，并说清“尺寸对不上（当初 875px，现在 2637px）”，交给人看一眼 |

守卫规则是熬出来的（每一条都是被误判逼出来的）：

1. **不比较视口 y**。元素在滚动容器里，滚一下就移位；实测表格只因消息流滚了 101px 就被判“不是原来那个”。
2. **数量只查变宽、不查变少**。列表/消息流是懒渲染的，数量本来就会变（实测表格从 10 个变 2 个，选择器一点没错）；但数量暴涨就是选择器变宽了，得拒。
3. **横坐标和尺寸要比**。左边缘一挪、尺寸一变大，多半就不是原来那个东西了。

推断下来就一句话：**“能匹配到元素”不叫修好了**。整个应用根 `body>div:nth-of-type(1)` 也“能匹配到”，
拿它去当侧栏会把整个界面改得一团糟。所以要拿当时记下的现场证据（匹配数 + 位置尺寸）卡一道，
过不了就停下来问人——这条命令的价值不是“全自动”，而是**把“悄悄坏了”变成“一条命令告诉你哪里变了”**。

## 踩过的坑（都是真踩的）

1. **别用 `nth-of-type` 链做选择器**。抓回来的路径是 `div>div:nth-of-type(2)>…`，看着像选择器，
   其实一改结构就断；而且路径被截断后拿去做 `querySelectorAll` 会从根上解释错。
   要挂就挂在语义类名 / 语义标签 / 令牌工具类上。
2. **同一个令牌可能既当底色又当字色**。`--cola-fill-black` 既是某个按钮的背景，
   也被几十处当文字色用（`text-[var(--cola-fill-black)]`）。子串匹配 `button[class*=fill-black]`
   会一次命中 68 个按钮，把主按钮样式糊到一片普通按钮上。要连着属性一起匹配：
   `button[class*="bg-[var(--cola-fill-black)]"]`。
3. **`:not()` 会被同一个坑反噬**。想在次要按钮上排除主按钮，写了
   `:not([class*='fill-black'])` —— 结果那些按钮的**文字色**里正含着这个令牌，
   全被排掉了，匹配 0 个。
4. **只量「挂着钩子的元素」会漏掉闯祸**。有些规则改的是子元素
   （`.loki-chat-stream > div { max-width: … }`），挂钩子的那层没变，子层被挤扁了。
   所以验证必须量**整页几何**。
5. **一起挂量不准归因**。父层钩子的 `font-size` 会继承给子层，子层明明没锅却记在它头上。
   要归因就得**逐钩子隔离**测。
6. **结构层的规则带着「自家版面」的假设**。同一批结构规则是给本套自带宿主写的；
   换到别人家，有些规则语义对得上（圆角、纹理、投影），有些对不上（给标题栏加贴纸边框，
   而对方的标题栏只有 32px 高 → 文字被裁）。**这类只能靠隔离测试撤下**，
   不要指望一次全绿 —— 撤下不是失败，是这次适配的正确答案。
7. **盘点器会拍到自己挂的钩子**。挂钩器一旦装上就会一直补挂，盘点时必然拍到
   `div.coding-cola-agent-session-item.loki-nav-item` 这种“回音”，候选里就全是自己加的名字。
   办法：分析阶段把我们自己的前缀滤掉（`probe.py` 的 `sanitize()`）——比去关观察器可靠，
   因为观察器可能有一份以上，关不干净。
8. **宿主的面板是懒挂载的**。它可能先有根节点、面板内容等第一次打开才建，甚至整个根节点会被
   换掉。挂钩器/注册器要是只盯那个具体节点，就会出现「注入时还没建，之后建好了却再没人来注册」
   —— 实测就是宿主面板里少了我们那 35 个条目。**盯 `document.body` + 防抖**，一定能等到。
9. **被剪掉的那套要是正在用，界面会掉样式**。用户把 35 套剪成 3 套、而他当前选的正是被剪掉的那套
   → 那套的 CSS 已经不在包里了。守护进程要自动回落到清单里的第一套（并写回存储键）。
10. **别用 DOM 深度做过滤**。侧栏在真实应用里常常在十几层里面，写个 `depth <= 9` 会
   把侧栏筛掉、只剩整个应用根。改用几何（够高够宽，但又不是整页本身）。

## 边界（说清楚，别指望一键通吃）

- **能过去的**：宿主里找得到位置的角色，都能挂上；挂上就吃 35 套里所有针对该角色的结构规则。
- **过不去的**：宿主里**根本没有**对应位置的角色（比如没有独立的品牌区元素），
  只能空着 —— 那个装饰位在这个宿主上是空的，其它套不受影响。
- **不能做的**：把本套自带的宿主专用配方（比如某个主题靠某个特定 DOM 结构才成立的效果）
  硬套到别人家。这不是接得不够勤快，是语义对不上。
- **每换一个宿主**，都要重新走一遍 ①→⑥。这份对照表是**这个宿主**的。
