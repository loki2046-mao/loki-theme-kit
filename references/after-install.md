# 装完之后：Agent 必须做什么 + 要交给用户的那段话

这个 Skill 的价值不只在"装上"，更在**装上之后用户还想要什么，他知道该说什么**。
所以装完必须主动交付一次信息，不要等用户自己翻文档、更不要让用户去终端粘命令。

---

## 一、Agent 装完必须做的三件事

1. **让提示页弹出来给用户看**：装完 `auto.py` / `start.py` / `install.py` 会自动生成
   `给你的用户.html` **并用浏览器打开**（`profile.py save` 也一样；不要弹就加 `--no-open`）。
   同一份内容另有 Markdown 版 `给你的用户.md`，可以直接转发。
   —— 不要指望用户自己去翻文档，他不翻的。
2. **明确说清这是第一层**：只到配色 + 基本字体圆角，结构件是另一层。
3. **告诉他下一句话怎么开口**：想要更多就说「连 UI 部件也一起变」。

**不要**把命令清单丢给用户。用户只会说人话，命令是你的事。

# 你的界面现在有 35 套外观主题了

## 一、现在就能用

打开页面 → **右下角会有「外观」按钮**（你的宿主自带皮肤面板的话，就多出一组
「LOKI 外观套组」，用的还是**你原来的那个入口**）→ 30 多套随便切。
你选的那套会被记住，下次打开还是它。

不想用了：**删掉那一行 `<script src="...">`**，或者告诉你的 Agent 一句，就全还原了。
你的项目文件除了那一行，没有被改过任何东西（改前都留了 `.loki-bak-*` 备份）。

## 二、先跟你说清楚一件事（免得误会）

**配色和整套 UI 是两层。**

- **第一层（已经装好了）**：配色、文字、边框、圆角、投影、字体、成功/警告/危险状态色。
  换一套 = 一眼就看出来变了。
- **第二层（还没做）**：侧栏、卡片、会话行、气泡、代码块、表格这些**具体 UI 部件**，
  也跟着变成这套主题的样子（纸面纹理、贴纸圆边、撕口、计数器编号、扫描线、四角准星…）。

第二层没法通用地搬过去 —— 每个界面的结构不一样，得**针对你的界面单独适配一遍**。
想要就跟你的 Agent 说一句：

> **「连 UI 部件也一起变」**

（如果你用的是改不了源码的桌面应用，也是同一句话；Agent 会自己在外面接上去。）

## 三、你接下来可能想要的，都在这里 —— 说一句话就行

**你不用开终端、不用粘命令，也不用手动改文件。** 对你的 Agent 说下面任意一句：

| 你想要的 | 你就说 | 你的 Agent 会做什么 | 你要额外做什么 |
| --- | --- | --- | --- |
| 换一套看看 | （自己点「外观」就行） | —— | 无 |
| **整套 UI 部件也变成这套主题的样子** | 「连 UI 部件也一起变」 | 盘点你的界面、认领角色、逐个部件挂上主题的结构件，再逐条实测有没有改坏排版 | 无（跑完看一眼效果） |
| **只要其中几套，其余不要** | 「我只要这几套，其余删掉」 | 重打包成只含那几套，其余从你的界面和文件里走掉 | 无 |
| **重启/升级之后，外观没了** | 「把外观恢复回来」 | 重新装回去；界面变了还会自动重新认领一次 | 无 |
| **不想每次都叫你，打开就有** | 「我要开机自动恢复」 | 装一个常驻守护：应用一起来，外观自己回来 | 无（可以随时一句关掉） |
| **我想自己新做一套** | 「按这张图/这个风格做一套」+ 给参考图或说风格 | 从参考图量色 → 起一套骨架 → 写结构件 → 过六道质检门 | 有图就给图，没图就说风格 |
| **我想沿用现成的一套，改一改** | 「就用这套，把主色改成 XX / 圆角改小 / 字体换掉」 | 复制那套成你自己的，按你说的改，再跑质检 | 无 |
| **我想把别人的主题搬进来** | 「把这个 theme.css 加进来」 | 放进 `sets/`、改好 id 和名字、并入接入包 | 把文件给他 |
| **这套我不要了，全部卸掉** | 「把外观全卸了」 | 删掉接入、清掉档案 | 无 |

## 四、"我选的那套会不会丢？" —— 讲清楚，别到时候懵

| 你的界面是什么 | 重启 | 应用升级 | 你要做什么 |
| --- | --- | --- | --- |
| 能改源码的项目（网页/自己的应用） | **在** | **在**（写进代码了） | 什么都不用做 |
| 改不了源码的桌面应用 | **会掉** | **会掉** | 说一句「把外观恢复回来」，或者装一次「开机自动恢复」让它自己回来 |

**为什么桌面应用会掉**：它是个打包好的程序，只能从外面挂上去，程序一重启就没了
（你的原文件一个字节没动，所以也不会有残留）。
**怎么让它不掉**：装一次常驻守护（对你 Agent 说「我要开机自动恢复」）。
之后不管是重启、退出重开、还是应用升级，**打开就是你的外观**。

**关于"沿用"的另一个提醒**：如果那个应用本来就有自己的皮肤系统，
我们**不会抢它** —— 你选它自带的皮肤时，我们自动让位；你选我们的套组时，
两套都还在，随时切回来。

## 五、想自己动手改？文件都在这儿

```text
<你的项目>/loki-themes/          ← 接入包（生成物，删掉即还原）
loki-themes.js                   自包含：35 套 + 切换器，一个文件
```

想真正改造一套主题，找你的 Agent 要 Skill 目录里的 `sets/`：

| 你想做什么 | 怎么做 |
| --- | --- |
| 改颜色 | `sets/<套组id>/theme.css` 顶部那一坨 `--bg-canvas` / `--text` / `--accent` … 逐条都是令牌 |
| 改形状/性格 | 同一个文件的**结构件**部分（圆角、边框、纹理、`::before` 编号、`::after` 撕口…）—— 这才是"一套主题"和"一个色卡"的区别 |
| 从一张图做新的 | Agent 跑 `palette.py 参考图.png` 量色 → `new-theme.py` 起骨架 → 写 6 条以上结构规则 → `check.py` |
| 沿用别人的 | 把别人的 `theme.css` + `meta.json` 拷进 `sets/`，改 `id`/`label`，就是你的 |
| 交付前自检 | `python3 scripts/check.py` —— 六道门：令牌完整 / 正文对比度 / 强调色上文字对比度 / **结构件数量（防"只是换了个色号"）** / 护眼专项 / 零素材依赖 |

## 六、这一包不会做的三件事（你的底线）

1. **没有任何图片文件。** 35 套全是纯 CSS，不夹带任何人的图。
2. **不含任何人的 IP 形象。** 换外观只换壳，不重画角色、不替换品牌位、不生成"第二个吉祥物"。
   装饰位留成变量，要图就用你自己的。
3. **不偷偷改你的东西。** 改任何文件前留备份；`--dry-run` 可以只看不动；一行接入随时删掉还原。

## 二、Agent 动作对照（用户说了那句话，你跑什么）

| 用户说 | 你跑 |
| --- | --- |
| 连 UI 部件也一起变 | 结构件适配全流程：`probe.py`（盘点）→ 定稿 `adapters/<宿主>/binding.json` → `adapt.py --check` → `--triage --apply`（隔离测试，把会弄坏排版的那几个撤下）→ `--verify`（结构件覆盖率 + 有没有藏元素）→ `--install`；改不了源码的宿主先 `inject-cdp.py` 打底。完事 `profile.py save` 存档案 |
| 我只要这几套 | `profile.py sets --name <档案> --only a,b,c` + `profile.py restore --name <档案>`（源码型宿主：`auto.py --project <路径> --sets a,b,c`） |
| 把外观恢复回来 | `profile.py restore --name <档案>` |
| 我要开机自动恢复 | `profile.py autostart`（`--status` 看、`--off` 卸） |
| 按这张图做一套 | `palette.py 图` → `new-theme.py --id … --palette 图` → 写 ≥6 条结构规则 → `check.py --only <id>` → `bundle.py --all --out <项目>/loki-themes` |
| 沿用现成的一套改 | 复制 `sets/<id>` → 改 `meta.json` 的 `id`/`label` → 改 `theme.css` → `check.py` |
| 把别人的主题搬进来 | 放进 `sets/`、补 `meta.json`、`bundle.py` 重新打包 |
| 全部卸掉 | `profile.py drop --name <档案>` + 源码型宿主删掉那行 `<script>`（注入型宿主重启即净） |
