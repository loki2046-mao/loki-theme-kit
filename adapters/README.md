# 宿主适配器（adapters/）

套组是通用的（令牌 + 契约钩子），但**每个宿主的变量名和 DOM 都不一样**。适配器就是那层翻译：
一个 `adapter.json` 声明"我们的哪个令牌接到宿主的哪个令牌"，`extra.css` 处理这个宿主特有的坑。

```bash
# 生成带适配的接入包
python3 scripts/bundle.py --all --adapter cola --out ./out
```

## adapter.json 的字段

| 字段 | 作用 |
| --- | --- |
| `id` / `label` | 适配器名字与说明 |
| `extra_selectors` | 我们的选择器模板，`__ID__` 会替换成每套主题的 id（`[data-theme]` 之外的写法） |
| `token_map` | `宿主令牌: 我们的令牌`。值以 `--` 开头会自动包成 `var(...)`，否则按原样写入（可写 `color-mix(...)`） |
| `important` | 宿主自己的皮肤用 `!important` 时就必须跟着加（否则压不过它） |
| `install.how` | `static`（能改源码，auto.py 那套）/ `cdp`（打包好的 App，从外面注入） |
| `install.yield_attr` | 宿主自己皮肤系统的属性名。它一变，我们的运行时就摘掉 `data-theme`，把界面还给宿主 |
| `install.orig_mode_attr` | 宿主记录"原始深浅模式"的属性（让位时要把深浅 class 还回去） |

适配器**不打包进套组**，只在生成接入包时叠加。所以同一套主题能同时服务多个宿主。

## 已适配：Cola（Electron 桌面应用）

```bash
python3 scripts/bundle.py --all --adapter cola --out /tmp/cola
python3 scripts/inject-cdp.py --port 9333 --css /tmp/cola/loki-themes.css --js /tmp/cola/loki-themes.js
```

Cola 是个**改不了源码**的宿主（打包好的 `.app`），但带调试端口，所以走 CDP 注入。

### 接法：注册进宿主自己的皮肤系统，不要另起一套

**第一版接错了，值得记下来。** 一开始我们按"通用 Web 宿主"接：设 `data-theme`、自带悬浮切换器。
结果四个问题全冒出来 —— 跟 Cola 自己的皮肤系统**打架**（两个切换器、两套状态）、悬浮面板
**挡住内容**、我们的面板**文字看不清**（宿主的 `button { color: … !important }` 漏进来了）、
而且**变化不够明显**（两套皮肤层叠着，互相抵消）。

改成"注册进宿主的系统"之后，四个问题一起消失：

| 做法 | 说明 |
| --- | --- |
| 主题名走宿主的属性 | 适配器声明 `install.attr = "data-cola-skin"`，我们的套组变成它的皮肤 id |
| 套组选择器同时匹配宿主属性 | `also_match_selectors` —— 不做这步，套组令牌根本不会被定义，`var(--bg-canvas)` 读出来是空的（踩过） |
| 用宿主的存储键 | `install.storageKey = "cola-skin-selected"`，跟它共用同一份记忆，不会两个键各记一半 |
| 注册进宿主的切换器面板 | `install.switcher`，我们的 35 套插在宿主的 `.css-grid` 里，带一个「LOKI 外观套组」分组标题；**不再有悬浮控件** |
| 宿主自己那套一动就让位 | 点宿主原有的按钮时，摘掉我们的标记属性，界面还给它的皮肤 |
| 宿主已有设计系统 → 不套通用元素层 | `skip_generic_layer` —— 我们那层 `button { background: accent }` 会跟它的按钮样式打架，实测出过 1.17:1 |

### 真机结论

| 维度 | 结果 |
| --- | --- |
| 令牌层 | 43 个 `--cola-*` / `--coding-cola-*`（含圆角、投影、字体、状态色、链接色） |
| 可读性 | 35 套 × 真实界面扫描：剩下的违规都是**宿主自己的**小字（它的切换器页脚 2.69:1 —— 在它自己的皮肤下也这样，我们的主题反而拍到 3.95:1） |
| 深浅色 | 10 套深色主题同步宿主的 `class="dark"`，宿主重设之后会被扳回来（它有自己的一套判定，不认识我们的主题名） |
| 入口 | 只有一个：宿主自己的切换器。面板加了一组「LOKI 外观套组」，并给它加了最大高度 + 滚动（原本 9 套两行刚好，塞 35 套会顶出屏幕） |
| 宿主文件 | **一个字节没动**（纯运行时注入，重启即恢复） |

### 适配过程中量出来的坑

1. **同一令牌既当底色又当字色**：宿主把 `--cola-highlight` 当"选中行底色"，我们按按钮语义映射成
   强调色 → 行里浅色标题压在亮底上，**1.54:1**。
2. **宿主的 `button { color: var(--accent-ink) !important }`**：把"压强调色的字色"套到所有按钮上，
   深色主题里 accent-ink 是近黑 → 落到深色底上 **1.03:1**。它还会漏进我们的 UI 里。
3. **套组选择器没跟着宿主属性改**：只设 `data-cola-skin` 而不把套组的选择器也挂上去，
   套组令牌压根没定义，适配层读到空值 —— 表现出来是"主题切了但界面没变"。
4. **渐变字（`bg-clip-text`）会让对比度扫描误报**：它的"字色"来自背景图，`color` 量不出对比度，
   扫描器要跳过这类元素。

### 方法论：可读性扫描

不要靠眼睛一处处找。遍历可见元素，算它的字色与**有效背景色**（沿祖先链找第一个不透明背景）
的对比度，低于 4.5:1 全报出来。第一版跑出 42 处，改完再跑到只剩宿主自己的小字。
**每次改适配器都要重跑一遍**——这类问题改一处会在别处冒出来。

### 已知边界（说清楚，别让人以为能一键通吃）

- **令牌层能过去的**：颜色、圆角、投影、字体、状态色 —— 宿主是变量驱动的就全套能过。
- **过不去的**：结构件（贴纸圆边、撕口、计数器编号、扫描线……）。它们挂在 `.loki-*` 契约钩子上，
  而 Cola 这类 Tailwind 宿主 DOM 里几乎没有语义类名（全是 `bg-[var(--cola-bg-surface)]` 这种
  工具类），**没有可钩的地方**。想让结构件过去得为宿主写一套结构适配，且随宿主改版会失效。
- 剩下的零散项：个别深色主题下会话行的元信息小字 4.24:1（略低于 4.5 的线）、行内代码在部分主题下
  偏淡。都属于"能看清但不够好"，需要时按同一套流程继续收。

## 适配器的两半：令牌 + 结构件

`adapter.json` + `extra.css` 解决的是**令牌那一半**（颜色、圆角、投影、字体、状态色）。
**结构件那一半**（纸面纹理、贴纸圆边、撕口、计数器编号、扫描线……）不在适配器里，
而在 `adapters/<宿主>/binding.json` —— 一份「角色 → 宿主里哪个元素」的对照表。

原因：令牌是**值**的映射，结构件是**元素**的认领。宿主没有 `.loki-*` 钩子时，
得先认领宿主自己的元素（`aside.coding-cola-agent-sidebar` 就是侧栏），
再由 `templates/tagger.js` 在运行时把钩子类名挂上去，35 套结构层就能原封不动生效。

```bash
python3 scripts/probe.py --port 9333                 # 出角色候选草案
python3 scripts/adapt.py --host cola --port 9333 --check     # 逐条实测
python3 scripts/adapt.py --host cola --port 9333 --triage --apply   # 哪个钩子会弄坏排版
python3 scripts/adapt.py --host cola --port 9333 --verify    # 结构件到了多少
```

完整方法与 Cola 上的真实数字见 `references/host-binding.md`。
